# The 3D renderer

This page describes how UW1 draws the 3D view: the C that turns the map around the player into a program for the renderer (`src/3d/*.C`), and the assembly renderer that runs that program (`src/3d/*.ASM`, DOS segment seg004, entered through seg019's C3DENTRY.ASM). The declarations, the vision grid flags (`GLOC_*`), the render database opcodes (`OP_*`) and the pick colours (`PICK_*`) are in `src/include/view3d.h`. The candidates for the findings page are in [3d-findings.md](3d-findings.md). Statements marked "probably" are inferences; the reason is given with each.

## Files

| File | Segment | What it does |
|---|---|---|
| `VIEW3D.C` | seg031 | places the view, sets up a frame, builds the vision grid, runs the renderer and shows the frame |
| `GRIDDB.C` | seg017_1FDD | turns the vision grid into render database bytecode, tile by tile; marks the automap |
| `SETPNT.ASM` | seg017_1FDD | `SetPnt`, which appends one point to the database; linked into GRIDDB.C's segment |
| `GAMESORT.C` | seg033_2EEF | orders each tile's objects for drawing |
| `DRAWOBJ.C` | seg032_2DCA | emits one object: a sprite, a critter frame, a 3D model or a door |
| `EXPAND.ASM` | seg004 module 1 | the image decoders (`uncmp_pal`, `exp_8str` and the rest) |
| `SMOOTH.ASM` | seg004 module 2 | `smooth_closure` and `smooth_over`, the Gouraud polygons |
| `CAMERA.ASM` | seg004 module 3 | `create_matrix` and the camera routines (UW1: a module of its own, with five camera types UW2 lacks) |
| `SPHERE.ASM` | seg004 module 4 | `sphere_check`, `get_dist`, `do_obj` and UW1's other object headers |

| `INTERP.ASM` | seg004 module 6 | the model interpreter's opcode handlers |
| `INSTANCE.ASM` | seg004 module 7 | `render_3d`, the transforms, clip codes, matrix products, divide-overflow handlers |
| `TMAPOPS.ASM` | seg004 module 8 | the texture-mapping opcodes, with UW1's own 16-bit clip and projection |
| `PGCACHE.ASM` | seg004 module 9 | textures and pictures from EMS, the critter page cache, `do_mouseq` |

seg004 is 9 modules where UW2's is 14 (TLINK's padding and the relocation order give the bounds; docs/NOTES.md, "seg004, the 3D renderer"). UW1 has none of UW2's 386 texture mapper (`CLIP`, `PERTLP`, `PERTP`, `PROJPOLY`, `SCANLINE`, `TEXMAP`, `TEXMAPV`): its textured polygons are clipped and projected in 16-bit code in TMAPOPS.ASM and filled by seg003's wall mappers (WALLMAP.ASM and POLYFILL.ASM, [gfx.md](gfx.md)). Every seg004 module assembles under `.186`. Names are UW2's (the FM Towns originals) where the routine is the same.

## A frame

1. The main loop calls `establish_view` (VIEW3D.C) through `do_3d_view` (game/UWEDIT.C). `render_FB` does the same but leaves the picture in the frame buffer, for fades and screens drawn over the view.
2. `setup_vars` has `get_eye` copy the player's position into the camera, `cPlayer` (`struct Camera`), and turns it into the first quadrant: the heading's octant picks a quadrant `quad`, the position within the tile is rotated to match, and the quarter turn is taken off the heading. From here on the C walks the map as if the player always faced the same way; `chgtable` turns steps and `trans_grid` turns tile types to match.
3. `do_2dclip` builds the vision grid (`init_grid`, `build_grid`) and calls GRIDDB.C's `process_grid`, which writes the frame's bytecode.
4. `send_db` sets the clip window to the view and calls seg019's `cRender`, which runs the bytecode into the frame buffer (seg004's `render_3d`, through a divide-by-zero handler of its own), and `cFBtoScreen` copies the frame buffer to the mode X screen with the mouse cursor hidden.

## The vision grid

`glocs` (VIEW3D.C) is 17 rows of 33 cells, one per tile: row 0 is the eye's row and column 16 its column, rows going away from the eye in the turned frame. Each cell is a `struct Gloc`: a flags byte (`GLOC_SEEN`, `GLOC_SHAPED` for a slope and with `GLOC_DIAG` a diagonal, the low two bits which way, and `GLOC_RIGHT`, `GLOC_FAR`, `GLOC_LEFT` the three faces that may show) and a shade byte (the distance shade in bits 0 to 3, 15 meaning too far; `GLOC_STEP_*` when the neighbour behind a face is open and higher, so the face reaches only its floor).

`preset_grid` fills the distance shades once (range 8) from the distance to the eye, scaled by the renderer's `smooth_div`, `smooth_lowpass` and `smooth_base`. `init_grid` starts two edges at the eye, aimed at the heading -0x2040 and +0x2040 (a full turn is 0x10000), and `build_grid` moves them out row by row, stopping at walls and marking every cell between a pair of edges with `enc_n_chk`, which looks the tile type up in `enc_dat` and drops the faces a neighbour at least as high hides.

## The render database

The render database is a buffer of the model interpreter's bytecode, written through `dbptr`; its labels are managed by `src/3d/GRDB.C` (`grdb_blank`, `Ref`, `gr_putlab`, `Clk`), and the 3D models' own bytecode lives in the renderer's far data. A frame's code ends with label 0xA0 and a 0 word.

An opcode is the byte offset of its handler in the opcode table at seg051:2738h (110 words, opcodes 0 to 0DAh); the handlers have the FM Towns names through UW2 and keep UW2's numbering. view3d.h names the ones the C writes: `OP_MOVEC` (a constant into a model variable, `Clk(n)`), `OP_SETCOLOR` and `OP_POLYRES` (a flat polygon), `OP_FETCHMAP` (a texture into a bitmap slot), `OP_TMAP`, `OP_COMPACT_TMAP` and `OP_COMPACT_WTMAP` (textured faces, the last when the view is level), `OP_OBJ` and `OP_SET_GMAP_CTXT` (the frame header), `OP_MOUSEQ` (end of a grid row), `OP_DEFRES`, `OP_UWOBJ` and `OP_UWCRIT` (sprites and critters), `OP_ORG`, `OP_SFCAL`, `OP_IHCALL`, `OP_DEFDELTA`, `OP_SET_TMCTXT` and `OP_SETTMOBJ` (3D models and doors), `OP_SETBMCOL` (the pick colour).

The table reaches handlers UW2 keeps without a table entry (`do_animate_p`, `do_animate_b`, `do_animate_h`, `do_setpat`, `do_putpat`, `do_usepat`) and UW1's own: opcodes 1Eh, 20h, 28h, 30h and 6Ah in SPHERE.ASM (object headers and a 32-bit world point), 24h and 52h in INTERP.ASM (per-step increments and relative points; not traced further). Unused slots point at `do_int2`, an `int 2`. The table is followed by two copies of the entries for 78h to 9Ch (2814h, the normal handlers, and 283Ah, NOCLIP.ASM's); `seg004_5040` only ever copies the normal set back.

## The renderer's data

seg004 runs with DS = seg051 (paragraph 4723, FD58). Each module names what it uses with equates (the names are ours, from INTERP.ASM's data map): the view matrix `MAT_XX` .. `MAT_ZZ` (1602h..1612h, 1.15 fixed point, `MAT_ab` input a's coefficient in output b), the point table `PNT_X` (1620h, 8 bytes a point: x, y, z, clip codes, shade), the clip code OR and AND (`CLIP_OR`, `CLIP_AND`), the polygon vertex buffers (`VBUF0`, `VBUF1`, `VB_START`, `VB_END`), the projection scales and screen centre (`PROJ_Y`, `PROJ_X`, `CENTRE_X`, `CENTRE_Y`), the eye (`EYE_X`, `EYE_Y`, `EYE_Z`, 32 bits each), the current object's origin and shift (`OBJ_X`, `OBJ_Y`, `OBJ_Z`, `OBJ_SHIFT`) and the polygon routines (`POLY_FILL`, `POLY_UFILL`). Clip codes are 1 x < -z, 2 x > z, 4 y > z, 8 y < -z, 80h behind the eye.

## Pick frames

`do_3d_grab` renders a pick frame (`do_3d_pickup`): every face and object is drawn flat in a colour that names it (view3d.h's `PICK_*`: objects 1 to 0xBF, walls 0xC0 + texture, floors 0xF0 + texture, the ceiling 0xFA), and INTERACT.C's `pick_3d` reads the colour under the pointer back through `color_to_obj` and `color_to_map` (192 entries each).

## Rules found in the code

- **Exploring pays.** `process_grid` counts the tiles that come into view for the first time (`pipeexp`) and, while the character's level is 1 to 15 and the map level is not 9, awards `pipeexp * PlayerLevel / 10` experience.
- **Level 9 is unlit.** On the map level 9 the frame is drawn with lighting off.
- **Detail.** `set_graphics_level` takes the detail setting (0 to 3) from the player record: from 1 the walls are texture mapped (`tmapson`), from 2 the floors, at 3 the ceilings too. Textured faces fall back to flat colour from the distance shade `distpoly` (7) on, and use a smaller copy of the texture from `dist8` (4) on.

## Open questions

- What UW1's own opcodes (1Eh, 20h, 24h, 28h, 30h, 52h, 6Ah) are used for; no model bytecode was traced.
- `render_3d` calls seg019's empty `_C10` in the middle of each frame on the graphics library's stack.
- The hallucination effect (`set_cyb`) changes words of the renderer's bitmap table that are probably texture coordinate masks; this was not checked in seg004.
